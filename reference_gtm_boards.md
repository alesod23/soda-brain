**The recurring pattern**: Alessandro hands over a batch of people to review before contacting.
That is now a **board** at `http://127.0.0.1:4141/b/<slug>`, not a one-off HTML file.

Per person the page shows: personal LinkedIn, org LinkedIn, org site, email with a
verified/pattern-guess badge and its source link, "why this person" evidence with a `[src]` link
per claim, an unverified-claims box, channel buttons (Email · Connect+note · LinkedIn DM · InMail,
auto-disabled when the person lacks the address or the profile), an editable message with a live
cap counter (300 note / 900 DM / 1900 InMail), Mark ready / Skip / Copy. Then one **Commit**
button freezes everything marked ready into `boards/<slug>/commits/<ts>.json`, and he says
"run the <slug> commit". `GET /api/queue` lists commits with no `executed_at`; stamp that field
after sending.

Key design point: `board.json` (evidence, generated by a per-board `build.js`) is kept apart from
`state.json` (his decisions). Research can be re-run and rebuilt without ever clobbering an edited
message. Decisions are server-side, not localStorage, so they survive a cache clear and a second tab.

**Chrome tab group "GTM"**: Chrome exposes tab groups ONLY to an extension holding the `tabGroups`
permission — no CLI, no CDP. `~/browser-extensions/gtm-tabs` polls `/api/tabs/pending` every 30s (Chrome clamps alarms to a 30s floor) and
files URLs into the group, finding it by NAME (a group id dies with its last tab). To put a page in
front of him: `POST /api/tabs {"urls":[...],"group":"GTM"}`. Queued URLs survive Chrome restarts.
Always put GTM pages in this group, even a single tab.

Server is kept alive by the existing `Coattio-Watchdog` task via `~/.medtech-crm/coattio-serve.ps1`
alongside 4124/4137/4139. To show a board: `~/gtm-eng/open-board.ps1 <slug>` — it queues the URL AND opens it in Chrome, so the
tab is instant and the extension only has to adopt it (the poll is 30s, Chrome's alarm floor).
Install the extension ONCE; after that everything is a script call.
