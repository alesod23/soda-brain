## How it works
- `watch.ps1` runs every 5 min via Task Scheduler task **`SODANOtif-Watch`** (replaced `SNM-Receiver`, which is now `/disable`d). 
- Fetches same sources as SNM/triage: Gmail cdtm+lobbly (unread + `triage/todo` carryover), WhatsApp (daemon, group-Me/done filtered), **Slack cdtm + horus** (Horus-KB = AllUnderground / MPD pilot customer workspace; xplore was DROPPED 2026-06-18 as dead).
- **Cost fix vs SNM:** content-hashes the fetched inbox arrays; if unchanged since last tick → skips the LLM entirely (steady state ≈ 0 tokens). Only classifies on change, and on **Haiku** (`claude-haiku-4-5`, env `SODANOTIF_MODEL` overrides), not Sonnet.
- Classifier = reuses SNM's `snm-receiver/prompt.md` + the live `/triage` SKILL body + user memory (so filtering matches real /triage), plus an appended note naming the cdtm/horus Slack workspaces.
- New actionable items → pushed to the bot via `push.js` (zero-dep, reads `~/.env/sodanotif.env`). Deduped via `notif-state.json#pushed` (sig = `source|from|snippet[:80]`, pruned 7d). Card: `SODANOtif | N new (M urgent) | HH:mm`, urgent prefixed `[!]`, top-5 + "N more".

## Control (sentinels in the dir)
- `focus` file present = quiet mode: urgent pings instantly, non-urgent buffers into a digest flushed every `SODANOTIF_DIGEST_HOURS` (default 3h). Absent = all-immediate (the default the user chose).
- `paused` file present = hard off, no scan.
- `DRY_RUN=1` env = log would-push + skip Telegram send AND skip cutoff advance (safe testing).
