**When Alessandro and I agree on a phased plan — "do v1 now, then v2 / these next steps later" — those later steps are a COMMITMENT, not a maybe. Do not let them silently drop.**

**Why:** 2026-06-20, on SODANOtif v2 the agreed step "open the source chat on the web in Comet when I need it" (workplan build-order step 7) was never built and, worse, never re-surfaced. Alessandro had to catch the omission himself and was (rightly) frustrated that he has to remember the roadmap for me. He wants planned next steps remembered AND proactively reminded — across different sessions/chats.

**How to apply (every multi-phase project):**
1. **Record the full roadmap durably** the moment we agree on it: a `WORKPLAN-*.md` with an explicit ordered "Remaining steps" list, AND mirror those remaining steps into the project's MEMORY file (memory loads every session; a workplan I might not re-open does not).
2. **Proactively resurface** the remaining agreed steps when resuming that project, or when a related task comes up — state "agreed remaining steps: …" BEFORE starting new/unrelated work, and ask if priorities changed.
3. **Tick steps off** in both the workplan and the memory as they're built, so the list stays honest.
4. This applies across sessions and chats — the memory mirror is what makes it survive a new session.
