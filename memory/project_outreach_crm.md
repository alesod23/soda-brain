Local **company-first outreach CRM** for Lobbly's IP design-partner outreach. Built 2026-05-26 from the brief at `OneDrive\KG Patent Idea\outreach\CRM-BUILD-BRIEF.md` (supersedes the old single-file `sme-outreach.html`).

- **Stack:** vanilla JS SPA + Node built-in `http` server (no deps). Three views: Today/Due, Companies, Templates. Time-based stage engine (working-days-aware): connect_sent +2 working days → email; dm_sent +4 cal days → email; email_sent +6 → bump; email_bumped +7 → stop. Coverage flag = company has ≥1 active person at a LIVE stage (dm_sent/email_sent/replied/engaged/…), else "no live thread".
- **App + seed (in OneDrive):** `OneDrive\KG Patent Idea\outreach\crm\` — `server.js`, `public/`, and the canonical seed `data/crm.json`.
- **GOTCHA — live data lives OUTSIDE OneDrive:** mutated state is `~/.lobbly-crm/crm.json`. A live-written file inside OneDrive gets sync-locked and atomic `rename` fails with EPERM. Seeded from the OneDrive seed on first run. Lock-safe timestamped backups mirror into `crm\data\backups\` (new file per save, never overwritten).
- **Run:** `$env:CRM_PORT="4123"; node "C:\Users\Alessandro\OneDrive - HEC Paris\KG Patent Idea\outreach\crm\server.js"` → http://127.0.0.1:4123 . Port via `CRM_PORT` env (default 4123).

- **Action recording (authoritative, server-side):** `recordAction()` writes the outcome of every Gmail/LI action onto the live data atomically and returns fresh state (`out.data`), which the client adopts (`DATA = res.data; render()`). Per-person `activity[]` (capped 50) renders as the "Activity log" on each card. Stage dates use local `todayISO()`; activity `at` is UTC ISO, displayed via `toLocaleString()`. **Failures + crashes also record** (`recordFailure()` → red `action_failed` entry) so NOTHING the user clicks is silently dropped — closes the gap where a LI send that errored (or landed but reported ambiguously) left no trace. The original "didn't record" miss was an action taken 17:07 before the recording code existed (19:05), not a logic bug. Static assets are served `Cache-Control: no-store`, so the browser never runs a stale `app.js`.
- **LinkedIn GOTCHA (root cause):** "session expired" errors were a FALSE ALARM caused by ~15 orphaned linkedin-mcp processes (incl. chrome-headless-shell) holding `…\profile\Default\Network\Cookies` locked (WinError 32) → feed-auth check fails → looks logged out. The session was actually VALID. **Fix = kill stray `linkedin-mcp` processes** (one-liner: `Get-CimInstance Win32_Process | ? {$_.CommandLine -match 'linkedin-mcp'} | % {Stop-Process -Id $_.ProcessId -Force}`), then `launcher.py --status` to confirm. Only if truly invalid: `launcher.py --login --no-headless` (the `--no-headless` flag is REQUIRED to show the login window; `--login` alone runs headless = invisible). Each crm_li.py call closes its browser but can leave an idle python MCP proc; pile-ups re-lock the profile. Caleb (`calebloveseeling`) = safe DM test card in "— Test / Sandbox".
