**His words (8 Oct 2026, SODA v2 planning):** the eval set "gets populated over time whenever I tell you some desired
outcome. In whatever session I tell it, you will always be able to understand ... Then you will compare with what's
already there, and you will figure out if there is a spot for it to create an eval."

**Why:** the v2 eval (events + desired outcome + the workflow + held-back rules) must grow from his real corrections,
not a one-off labelling session; a desired outcome said in passing is the best ground truth there is.

**How to apply:** when he says what should have happened ("it should have been in my draft", "ONE draft with the deck
and the slots"), besides filing the rule, check the eval set (location fixed in the v2 design, see the soda-brain
workplan, 8 Oct SODA v2 line) for a case covering that event; if none, add one (event, desired outcome, source quote).
