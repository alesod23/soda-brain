`C:\Users\Alessandro\.claude\tg-bridge\` — a Telegram bot (zero-dep Node long-poller, `bot.js`) that forwards each phone message to headless `claude -p` on the Windows machine. The bot is a DUMB PIPE; all intelligence is in the appended `routing-prompt.md` (read fresh per message — edit it to tune, no restart). Routing: tasks→`/dump` (task-land), personal notes→`/kb-ingest` self-reflection-wiki, knowledge→vault_kb/thesis-kb, questions (incl. "what's on today")→answered from `task-land/Daily/`.

Built 2026-06-04 after Alessandro wanted to dump thoughts / view today's tasks from his phone. Channel chosen: Telegram (clean, no risk to wa-daemon session). Scope: dump-only-for-now BUT expanded to general vault-ingest + ask-anything.

Key facts:
- Flags: `claude -p "<text>" --append-system-prompt <routing-prompt.md> --permission-mode bypassPermissions --add-dir <home> [--strict-mcp-config]`.
- **MCP is HYBRID** (env `MCP_MODE=hybrid`, default; also `always`/`off`). Per message `decideMcp()` regex-matches the text (calendar/schedul/event/meeting/email/gmail/notion/send-a-message/etc.): match → load FULL MCP (no `--strict-mcp-config`, ~20s boot, gets Calendar/Gmail/Notion/Drive/LinkedIn/Zotero/Langfuse); no match → `--strict-mcp-config` (zero servers, ~3s). Per-message override prefixes: `+mcp` forces on, `+nomcp` forces off. Curated subset is IMPOSSIBLE — Calendar/Gmail are claude.ai-scope connectors that only load with the full set (verified 2026-06-07: full load ~20s, lists calendars fine). Send safety in `routing-prompt.md`: additive actions (create event, add task/note) just execute; RISKY (email/LinkedIn/WA sends, calendar delete/edit) DRAFT-only unless the msg says dsend/"send it"/quoted — stateless so the draft is echoed for re-send approval.
- Long-polling `getUpdates` — no open port / no webhook / no ngrok. Serial queue (one Claude at a time).
- Locked to single `ALLOWED_CHAT_ID`; `/id` returns chat id for bootstrap. Env at `C:\Users\Alessandro\.env\tg-bridge.env` (token key = **`TG_BRIDGE_BOT_TOKEN`** since 2026-06-21; renamed from the bare `TELEGRAM_BOT_TOKEN`, which collided across 4 bot env files in the auto-loaded global shell and leaked a wrong token into the official telegram plugin — see [[reference_telegram_channel_plugin]]). `bot.js`/`send-to-phone.js` read `env.TG_BRIDGE_BOT_TOKEN`.
- Lifecycle: `start.ps1` / `stop.ps1` + `keep-awake.ps1` watcher (SetThreadExecutionState power-lock; blocks IDLE sleep only — manual lid-close/Start→Sleep still sleeps), mirrors [[reference_wa_sender]]'s wa-daemon pattern. Logs: bot.log / bot.log.err. `start.ps1` is idempotent and spawns keep-awake watching the bot PID; keep-awake self-terminates when the bot dies. `bot.js` owns `bot.pid` (writes on start, unlinks on exit) — start.ps1 itself does NOT write it.
- **keep-awake is UNCONDITIONAL (AC + battery) by deliberate user choice (2026-06-09).** It holds the system awake whenever the bot lives, regardless of power source — identical to `wa-daemon\keep-awake.ps1`. An AC-only variant (release lock on battery) was built and tested, then REVERTED at the user's request: they want the bot reachable whenever the laptop is open, and accept that "lid closed in a bag" / manual Sleep is the off-switch. DO NOT re-add a battery/AC guard unless the user explicitly asks. NB: the wa-daemon watcher also pins the system awake unconditionally, so the laptop never idle-sleeps while EITHER daemon runs (only lid-close/manual-sleep/reboot sleeps it).
- **Photos supported (added 2026-06-17):** sending a photo (or an image document) makes bot.js download it via getFile→file-CDN, re-encode to a real PNG via GDI+ (`powershell System.Drawing`, JPEG→PNG since the paste AHK only matches `*.png`), and save it to `OneDrive - HEC Paris\Pictures\Screenshots\` as `Screenshot YYYY-MM-DD HHMMSS.png` (env `SCREENSHOT_DIR` overrides). This feeds the existing **`Ctrl+Alt+V`** AHK (`copy newest screenshot (ctrl alt v).ahk` — copies newest `*.png` from that folder as CF_HDROP + pastes; accepted by the Claude CLI). Images bypass the Claude queue (plain file op). Voice still ignored.
- **Laptop→phone sender (added 2026-06-17):** `tg-bridge\send-to-phone.js` (zero-dep) POSTs a string to the locked chat as a Telegram `code` entity = one-tap-copy on the phone (for IPs/URLs/tokens). `node send-to-phone.js "text"`, also stdin + `--plain`. Reuses tg-bridge.env token/chat-id. Trigger phrase: "send/telegram/push X to my phone" → main agent runs it.
- Each `claude -p` call is a fresh process, BUT it now carries **short-term memory** (added 2026-06-10): a rolling transcript `tg-bridge\history.jsonl` (JSONL `{ts,chat,role,text}`, keyed by chat). bot.js `readHistory/formatHistory/appendHistory` feed the last 16 turns (≤4000 chars) into the `--append-system-prompt` after the routing prompt, so the bot resolves "this"/"the last one"/"reverse that" and knows what it just did. Tunable via env `TG_HISTORY_TURNS/MAXCHARS/KEEP/FILE`; file self-prunes to last 400 lines. `routing-prompt.md` line ~40 updated (no longer claims "stateless"). Verified end-to-end 2026-06-10 (injected transcript → recalled the fact). It's CONVERSATIONAL memory, not a durable facts store.
